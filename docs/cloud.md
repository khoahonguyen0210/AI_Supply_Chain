# Cloud mapping (AWS, Terraform)

`infrastructure/terraform/` describes how the local stack would run on AWS. It is architecture as code: it passes
`terraform validate`, `terraform fmt -check` and `tflint`, but it has never been applied, and nothing in the project
needs an AWS account. Every cloud piece has a local equivalent that the tests, the demo and the benchmarks use.

## Architecture

```
            internet
               |
        ALB (public subnets, HTTP or HTTPS with an ACM certificate)
               |
   ECS Fargate, private subnets, Service Connect namespace scm-<env>
   +------------+     +-----------+      +----------+
   | frontend   | --> | backend   | ---> | engine   | -- EFS (agent tasks, approvals)
   | Next.js    |     | API       |      | 1 task   |
   +------------+     +-----------+      +----------+
                           |                   |
                      +----------+             |
                      | worker   | x1..N  (backend with the job worker + engine sidecar on 127.0.0.1)
                      +----------+             |
                           |                   |
                 RDS PostgreSQL 16 + pgvector  +-- S3 artifacts (gateway endpoint)
                 (records, job queue, audit, knowledge base)
```

The topology is the kind deployment's ([kubernetes.md](kubernetes.md)), one ECS service per Kubernetes deployment.

## What maps to what

| Concern | AWS (Terraform file) | Local equivalent |
|---|---|---|
| Relational database | RDS PostgreSQL 16, encrypted gp3, TLS required, 7-day backups, deletion protection (`data.tf`) | `pgvector/pgvector:pg16` container (Compose) or pod (kind) |
| Vector store | pgvector in the same RDS instance; Flyway migration V2 creates the extension | the same image |
| Job queue | the `job` table in PostgreSQL, claimed with `FOR UPDATE SKIP LOCKED` ([async-jobs.md](async-jobs.md)); no SQS needed | the same table |
| Object storage | S3 bucket, versioned, encrypted, public access blocked, old versions expire after 90 days (`data.tf`) | `ml/artifacts/` and `ml/experiments/` on disk |
| Engine state | EFS with an access point owned by uid 10001, IAM-authorized mount (`data.tf`) | `engine-state` volume (Compose) or PVC (kind) |
| Container registry | ECR per image, scan on push, immutable tags except `main`/`latest`, lifecycle rules (`registry.tf`) | local images `scm-*:local`; GHCR from CI ([ci.md](ci.md)) |
| Compute | ECS Fargate services `frontend`, `backend`, `engine`, `worker`, plus a one-off `seed` task (`compute.tf`) | Compose services / kind deployments and the seed job |
| Service discovery | ECS Service Connect: `backend:8080`, `engine:8001` | Compose DNS / Kubernetes Services |
| Load balancing, TLS | ALB, HTTP to HTTPS redirect, TLS 1.2+ policy; `certificate_arn` is required unless `allow_plain_http = true` | frontend published on 127.0.0.1:3000 |
| Scaling | Application Auto Scaling, worker 1..N on 60% average CPU | `scripts/kind.sh scale N` |
| Secrets | Secrets Manager: generated at apply time and written through write-only arguments, so they never land in state; injected as ECS secrets (`data.tf`) | `.env` generated by `scripts/stack.sh up`, `secrets.env` for kind |
| IAM | execution role (pull, logs, read the app secret), one task role per service (only the engine may touch S3/EFS), GitHub OIDC role for CI to push to ECR, limited to `main` and `v*` tags (`iam.tf`) | none needed; the app's own JWT/RBAC applies in both ([security.md](security.md)) |
| Network | VPC across 2 AZs, public subnets for ALB and NAT, private subnets for tasks, database, EFS; the database and EFS accept traffic from tasks only (`network.tf`) | Compose network, ports bound to 127.0.0.1 |
| Logs | CloudWatch log group per service, retention `log_retention_days` (`observability.tf`) | `docker compose logs`, `kubectl logs` |
| Metrics | Container Insights (enhanced), ALB and RDS metrics; the backend's Prometheus endpoint on 8081 is unchanged | Prometheus endpoint on 8081, `/api/ops/*` ([observability.md](observability.md)) |
| Alarms | SNS topic (optional email); ALB 5xx rate > 5%, no healthy frontend, no running backend/engine/worker task, RDS CPU > 80%, free storage < 2 GiB | operations page in the frontend |
| LLM | optional: `planner = "claude"` reads `ANTHROPIC_API_KEY` from its own secret | `SCM_ML_PLANNER=claude` and the key in `.env`; default is the offline rule planner |

## Choices and limits

* Fargate rather than EKS: the stack is five containers with no cluster-level needs, and Fargate has no control plane
  fee. The kind deployment already shows the Kubernetes version.
* The engine stays a single task because its SQLite state is single-writer (`deployment_minimum_healthy_percent = 0`,
  the same as `Recreate` in Kubernetes). Workers scale because their engine sidecars keep state in memory.
* Workers scale on CPU, not queue depth: a worker is CPU-bound while it runs a job. Scaling on
  `scm_jobs{status="QUEUED"}` would need that gauge exported to CloudWatch, for example with an ADOT collector sidecar.
* The engine connects to PostgreSQL with `sslmode=require` and reads the password from `PGPASSWORD`, so no connection
  string holds a secret. The backend's JDBC driver negotiates TLS by default, which `rds.force_ssl` requires.
* The application does not read from or write to S3 yet: training and evaluation write to local directories. The
  bucket and the engine's permissions are where a retraining job would publish artifacts ([feedback-loop.md](feedback-loop.md)).
* Cost was not measured. Running it would bill at least the NAT gateway, ALB, RDS, EFS and the Fargate tasks.

## Using it

```bash
cd infrastructure/terraform
cp terraform.tfvars.example terraform.tfvars    # adjust
terraform init
terraform plan                                   # needs AWS credentials; not run in this project
```

Push the images to the ECR URLs in the `ecr_repositories` output with the tag in `image_tag`, apply, then run the
`seed_command` output once the backend is healthy. The demo password is the `SCM_DEMO_PASSWORD` key of the
`app_secret_arn` secret.

Check it without an AWS account (Docker; on Windows copy the folder to a path without `&` first):

```bash
docker run --rm -v "$PWD/infrastructure/terraform:/tf" -w /tf hashicorp/terraform:1.16.4 init -backend=false
docker run --rm -v "$PWD/infrastructure/terraform:/tf" -w /tf hashicorp/terraform:1.16.4 validate
docker run --rm -v "$PWD/infrastructure/terraform:/tf" -w /tf hashicorp/terraform:1.16.4 fmt -check
docker run --rm -v "$PWD/infrastructure/terraform:/data" -w /data --entrypoint sh \
  ghcr.io/terraform-linters/tflint:v0.64.0 -c "tflint --init && tflint"
```
